# 纸面实盘使用手册(T012)

> 本文是个人研究记录的使用说明,**不构成任何投资建议**。周报里的任何数字都只说明"这套规则在这段样本里的表现",不代表未来收益。
> 本项目不接任何交易接口:所谓"真实成交",是你自己在券商 App 里下单后,**手工把成交结果记到一个本地 SQLite 日志里**,用来和系统的理论信号对比。

## 1. 整体流程(一周的节奏)

```
每个交易日收盘后    系统每日任务写账本(signal_ledger)→ 你看到"今日买卖"清单
T+1 开盘后 30 分钟  你在券商 App 用限价单执行(固定执行窗口)
当天收盘后          你把成交/漏单录入模拟盘日志(PaperJournal)
每周末              运行 scripts/weekly_summary.py 生成周报 → 你读周报
```

三个数据源各管一件事,**互不写对方**:

| 数据 | 文件 | 谁写 | 周报怎么用 |
|---|---|---|---|
| 系统发了什么信号、事后对不对 | 账本 `signal_ledger.db` | 每日任务 | 只读(`sqlite mode=ro`) |
| 你实际怎么下单、成交价多少 | 你自己建的日志,如 `data/paper/journal.db` | 你(手工录入) | 只读/不新建 |
| 大盘日收益 | 你导出的 CSV(`date,ret` 两列) | 你 | 停止规则的对照基准 |

日志文件名**不能**叫 `simtrade.db` 或 `signal_ledger.db`(代码会拒绝,防止误改已有库)。

## 2. 生成周报

```
.venv/bin/python scripts/weekly_summary.py --week 2026-W44 --journal data/paper/journal.db --initial-cash 100000 --benchmark-csv data/paper/hs300_daily.csv
```

- `--week` 缺省为上一个完整周(ISO 周,周一到周日,与晋升门槛的周口径一致)。
- 不传 `--journal`:仍能出周报,但"成本后收益/换手/执行偏差/仓位/单日亏损"几节写"数据不足"。刚开始、还没记成交时这是正常的。
- 不传 `--benchmark-csv`:停止规则写"无法判断:缺基准"。**脚本绝不会用全市场等权平均冒充大盘**(那是衡量选股能力的另一个口径,不是"赚不赚钱"的口径)。
- 输出到 `handoff/reports/weekly/<周>.md`;同名文件已存在时**拒绝覆盖**(退出码 2),想重跑请换 `--out-dir` 或自己先移走旧文件。
- 全程只读、不联网、不弹通知。

## 3. 每周怎么读周报(从上往下,先看风险,后看收益)

1. **最顶部的警示块**:出现"⚠ 暂停实盘""⚠ 风控违规""单日亏损停手""有信号未登记"时,先处理这些,再看别的。没有警示块不等于策略有效,只等于没触发规则。
2. **第 1 节 精确率**:主策略按 h=5/20 日的命中率,带 Wilson 置信区间。看"区间下限"而不是点估计;样本不足(<30 条或 <5 个信号日)会标"仅观察"。账本目前信号日很少,前几周大部分是"数据不足",正常。
3. **第 2 节 召回率与漏掉的上涨股**:事后涨幅前 5% 的股票里,系统推荐/持有了多少、被过滤了多少、完全没信号多少。看 `lift`(比随机撒网强多少倍)。
4. **第 3 节 随机对照与晋升进度**:主策略和"1000 次匹配随机抽样"比较,显示假设总数 m 与 Holm 校正是否通过。**候选越多,最好的那个越可能是运气**——所以"在噪声范围内"是默认状态,不是 bug。晋升门槛(≥12 周、≥500 信号、Holm 通过)不会因为你想快而放宽。
5. **第 4–5 节 成本后收益、回撤、换手**:净值已含手续费与实际成交价(现金口径)。只有"自第一笔成交日起"的数据,窗口短时夏普、回撤都不稳定。换手是单边简版口径。
6. **第 6 节 执行偏差**:你的成交价比信号日收盘价差多少,并拆成两部分:
   - **隔夜跳空**(市场造成,不可避免)+ **执行滑点**(你的执行造成)= 总偏差;
   - 正数 = 对你不利;买入和卖出方向公式不同(卖出时高开对你有利),周报已分方向计算;
   - 同时给出漏单率与原因(涨跌停/停牌/没来得及/其他)、偏差最大的 5 笔、以及"未登记信号"。`too_late` 占比高说明是执行纪律问题,不是策略问题。
7. **第 7 节 规则状态**:见下文第 5 节。
8. **第 8–9 节 反思摘录与固定尾注**:尾注是每周必带的自检清单(样本量、多重检验、成本、过拟合、幸存者偏差)。

读完请自问:这周的好看数字,有没有可能只是样本太少或挑出来的最好那个?

## 4. 怎么记录真实成交(PaperJournal)

**使用约定(违反会导致报告被拒或失真):**

1. **必须从空仓起算。** 日志窗口起点不能有持仓。第一笔真实成交的日期就是统计起点;如果你已经持有股票再开始记,`report` 会拒绝。要中途开始,请在一个空仓的日子重新开始,并写明起点。
2. **一个信号对应一条记录。** 每个系统信号先登记(日期、代码、买/卖、理论价、策略名),再登记成交或漏单——二者只能选一个。
3. **理论价 = 信号日收盘价**(账本里的 `close`)。成交价与它的差就是总偏差。
4. **执行窗口固定:T+1 开盘后 30 分钟内,用限价单。** 不要事后挑个好价格补记。窗口外成交、盘中看涨跌再决定的,请在 `note` 里写明,周报会把它当执行问题看待。
5. **成交时间带时分**,如 `2026-10-26 09:41`。同一时刻同价同量的两笔会被当作重复(幂等规则);确有两笔就带上秒或序号区分。分批成交就多登记几条 fill。
6. **手续费如实填**(佣金、印花税、过户费)。净值计算会扣。
7. **没成交也要记**:涨停买不到、停牌、没来得及,用 `add_miss` 记原因(`limit / suspended / too_late / other`)。**不记等于未登记,周报会提醒**——否则人会倾向只记成功的单,漏单率就被低估了。
8. **每天给持仓记一个估值价**(`add_mark`,通常用收盘价),否则无法算净值和仓位权重。同日同票不同价会报错,不会覆盖。
9. 录错了可以 `delete_fill / delete_signal` 后重录;**不要直接改库文件**。

最小示例(交互环境里运行;路径换成你自己的,日志文件第一次实例化时创建):

```python
from src.validation.paper import PaperJournal

with PaperJournal("data/paper/journal.db") as j:
    sid = j.add_signal("2026-10-23", "600000", "buy", 10.00, "blend2")
    j.add_fill(sid, 10.04, 1000, "2026-10-26 09:41", fee=5.0, note="限价单")
    j.add_mark("2026-10-26", "600000", 10.10, "收盘价")
```

## 5. 三条规则是什么意思

这三条来自规划 PDF,实现在 `src/paper_review/rules.py`,是**只给提示的纯函数**:周报只报告,不会替你下单、清仓或停止任何程序,**动作由你自己做**。

| 规则 | 默认值 | 含义 |
|---|---|---|
| 停止标准 | 连续 3 个月,每月跑输大盘 ≥3% | 触发即"暂停实盘",回到纸面,复盘后再决定 |
| 仓位约束 | 单票 ≤10%、总仓 ≤80% | 分母是总净值(含现金);**严格大于**才算违规(正好 10%/80% 合规) |
| 单日亏损 | 当日亏损 ≥2% | 分母是**前一日收盘净值**;"停手"建议为当日不再新开仓(可卖出/减仓,不强迫你扛亏损) |

需要你知道的细节:

- **停止标准的读法**。默认读法 A:连续三个自然月、**每个月**都比大盘差 3% 以上才触发;刚好 −3.00% 算触发。读法 A 很严格,几乎不会触发——这不是 bug。若你更想要"最近 3 个月累计落后 3%"(读法 B),函数有 `mode="cumulative"`,但周报默认仍是 A,改默认需要你拍板。
- **月份必须完整、日历连续。** 当月未结束,或共同交易日少于 10 天的月份不计入;中间缺月会让连续链中断,结果是"数据不足",而不是"未触发"。
- **"大盘"口径**。推荐沪深300ETF(510300)日收益,自己导出 CSV。停止规则比较的是"你赚不赚钱 vs 大盘",和精确率里"相对全市场平均"不是一回事,周报分开标注。
- **数据不足 ≠ 安全。** 看到"数据不足"说明还判断不了,不是说没问题。
- 这些规则不能代替晋升门槛:纸面实盘 → 小额实盘还要求 ≥3 个月、实盘与回测偏差稳定;小额 → 加仓要求 12 个月滚动超额 >0 且最大回撤 <15%。
- 规则或参数的改动隔日生效并记录,不要在亏损当天临时改规则(心理纪律)。

## 6. 常见问题

- **周报大部分节是"数据不足"?** 正常。账本信号日少、日志刚开始时就是这样。PDF 的前提也是:前 6–12 个月"系统很漂亮、收益约等于大盘"不算失败。
- **会弹 Mac 通知吗?** 现在不会。周报只在文件里写警示;接入通知见 `handoff/reports/T012_site_proposal.md`,默认关闭、需要另行批准。
- **能直接看到网站上的风控提示吗?** 还不能,网站接入只是提案,未经批准不改网站。
- **回测/周报好看是不是策略有效?** 不一定。要同时考虑:样本量(<12 周、<500 信号时只算观察)、多重检验(候选越多越容易挑到运气好的)、过拟合、交易成本与执行偏差、幸存者偏差。
