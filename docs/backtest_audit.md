# 回测引擎审计(T011 · S0,只读)

> 范围:`src/backtest.py`、`portfolio.py`、`strategy.py`、`strategies.py`、`indicators.py`、`simtrade.py`、`trade_list.py`、`signal_ledger.py`、`scan.py`、`registry.py`(回测部分)、`datasource.py` / `allmarket.py`(复权与停牌)、`metrics.py`;返工补充:`engines/`(backtrader / RQAlpha / inhouse / custom)与 `amibroker/ma_cross_adx_atr.afl`(见 §1.13)。
> 方法:只读代码,没有运行任何回测,没有读取 `data/` 下的真实数据,没有联网。凡是依赖"外部规则事实"(税率生效日期、涨跌幅制度)的结论,我是凭记忆写的,标了 **[需核实]**,S1 或所有者要对照交易所公告确认。
> 状态词:**已建模** / **未建模** / **建模有误**(有建模但与规则不符,或口径互相矛盾) / **无法判断**(代码里看不出来,需要数据或运行才能确认)。
> 风险等级:高 = 会让回测明显偏乐观或得出相反结论;中 = 影响收益数字、不改变结论方向;低 = 边角情形。

## 0. 先说结论(给面试时讲的版本)

1. 项目 `src/` 内其实有 **三套** 撮合口径,不是一套(注意:这和 CLAUDE.md 里说的"三个引擎(自研 / backtrader / RQAlpha)"**不是同一个划分**——后者在 `engines/`,见 §1.13):
   - `backtest.py`:单品种逐笔,**只服务于和 AmiBroker 对照**,没有任何 A 股规则(无整手、无涨跌停、无印花税、无停牌)。
   - `portfolio.py::run_weights`:目标仓位引擎,**扫描、网页回测、清单里的历史绩效都是它**。A 股规则只有"单边固定 8bp 费用"和"开盘涨跌停挡单"。
   - `simtrade.py`:模拟盘,**规则最完整**(整手、最低佣金、过户费、印花税、T+1、涨跌停、停牌),但只管"今天之后"的纸面成交,不参与历史回测。
   所以:历史收益数字(portfolio)比模拟盘(simtrade)的规则**宽松**,两者不能直接比较。
2. 没有发现"明显的未来函数":信号只用 t 日收盘及以前,成交在 t+1 开盘,15:30 前的当日 K 线被丢掉,后复权不会把未来分红带进过去价格。
3. 最需要关注的不是某一行写错,而是:**费用被简化成对称 8bp**(忽略印花税单边和 2023-08-28 税率下调)、**涨跌停阈值有 4 份互相不一致的实现**、**涨跌停挡单没有直接的单元测试**、**ST 状态用的是"今天的名字"套到全部历史**。
4. 目前没有任何一处会让回测收益**系统性大幅虚高**,但有若干处会让它**比真实交易乐观几个 bp 到几十 bp/年**(见下表),并且高换手策略(rsi2、donchian)受影响最大。
