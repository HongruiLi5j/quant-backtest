# 持仓台账使用说明

持仓台账回答三个问题：**我现在持有哪几只股票、各持有多少股、什么时候买的**，并给出平均成本、浮动盈亏和占总资金比例。所有数据由你在网页上手动录入、手动撤销。

**只记录，不连接券商，不下单，不自动同步成交。** 台账记的是"我实际做了什么"，不是系统的建议。设计细节见 `docs/holdings_design.md`。

## 1. 如何开启

持仓页只在个人模式下存在。个人模式默认关闭，开启与关闭方法见 `docs/personal_mode_howto.md`，开启命令是：

```sh
.venv/bin/python -B -c 'from pathlib import Path; Path("personal_mode.json").write_text("{\"enabled\": true}\n", encoding="utf-8")'
```

刷新网页后，个人导航会出现第 6 项 **持仓**（英文 Holdings），也可以直接访问 `#/holdings`。

- 关闭个人模式（`enabled` 改为 `false`）后，持仓入口消失，`/api/holdings*` 的表现与不存在的路径一致（404），`#/holdings` 回到今日页且不发任何持仓请求。
- 关闭个人模式**不会删除数据**：`data/holdings.db` 原样保留，再次开启即可继续使用。
- 必须通过本机地址（`127.0.0.1` / `localhost`）访问，并带有效的网站会话 cookie。

## 2. 页面上有什么

1. **汇总**：总资金（点"修改"就地编辑）、持仓市值、已投入占比、浮动盈亏、已实现盈亏、现金分红；现价取不到的持仓会提示"n 只价格不可用"。
2. **当前持仓**：代码、名称、股数、平均成本（含费用）、现价及价格日期、浮动盈亏与比例、占总资金比例、首次买入日、持有天数。默认按占比从高到低排序，单票占比超过 10% 会标红（仅作展示提醒，不会阻止录入）。
3. **录入成交**：见第 3 节。
4. **成交历史**：倒序列出，可勾选"显示已撤销"；每笔有"撤销"按钮。
5. **已清仓历史**（折叠）：卖光的那一轮的首次买入日、最后卖出日、持有天数、盈亏。

## 3. 录入规则

先填表，点"提交"会弹出**确认摘要**（例如"买入 600xxx 名称 1000 股 @10.000，费用估算 5.00"），确认无误再点"确认入账"才真正写入。表单每次打开都带一个随机 `client_id`，网络抖动导致的重复提交只会入账一次。

| 字段 | 规则 |
|---|---|
| 日期 | `YYYY-MM-DD`，按**北京日期**判断，不能晚于北京的今天，不早于 1990-12-19 |
| 代码 | 6 位数字，只支持沪深 A 股（60/68/00/30 开头）和沪深 ETF；北交所、港美股、可转债等一律拒绝 |
| 方向 | 买入 / 卖出 / 送转（送转股、拆股）/ 分红（现金分红） |
| 数量 | 正整数。买入：普通代码须为 100 股整数倍；科创板（688/689）每笔买入至少 200 股（代码实现按每笔校验）；卖出可以是零股，但不能超过持股；送转为新增股数；分红填登记日持股数 |
| 价格 | 大于 0、最多 3 位小数。分红填**每股税后到账现金**。送转价格固定为 0 |
| 费用 | 可留空。留空时按模拟盘的费率公式估算，并标"估算"；该费率**尚未与真实账户核对**，建议填券商账单上的真实费用（佣金 + 过户费 + 印花税合计）。最多 2 位小数 |
| 备注 | 可选，最多 200 字符 |
| 来源信号 | 可选，格式 `日期\|策略\|代码`，其代码须与本笔代码一致 |

不认识的字段、错误的格式会被整笔拒绝，错误提示是固定文案，不会回显你输入的数量或价格。

### 计算口径（面试可讲）

- **加权平均成本含费用**：买入 `成本 += 数量 × 价格 + 费用`；均价 = 总成本 ÷ 股数。
- **卖出不改均价**：已实现盈亏 = 卖出所得（扣费用）− 卖出股数 × 当时均价。
- **首次买入日**：持股从 0 变为正数那天的买入日；卖光后再买，重新计算。
- **持有天数**：北京日期的自然日差，当天买入为 0。
- **浮动盈亏**：`(现价 − 均价) × 股数`，不扣预估的卖出费用。
- **金额全部用整数存储（价格 0.001 元、费用 0.01 元）、`Decimal` 计算**，避免浮点误差。
- 现价取自本地日线缓存的最近收盘价（不含盘中半根 K 线），不是实时价；取不到就显示"价格不可用"，不会用成本价或 0 顶替。

## 4. 撤销规则

- 台账**不物理删除、不修改**已入账记录。录错了：撤销那一笔，再录入正确的一笔。
- 撤销是软删除，需要二次确认；已撤销的记录在历史里灰显、划线，且不再参与任何计算。
- 每次新增或撤销，系统都把全部未撤销记录**按日期和录入顺序整体重放**，所以均价、首次买入日、已实现盈亏永远与历史一致，没有会过期的累计值。
- 如果一次撤销会让后面的卖出变成"卖得比持有的多"，会被拒绝（`HOLDINGS_VOID_BREAKS_HISTORY`），请先撤销后面的卖出。补录更早日期的记录同理：任何时点出现超卖、或送转/分红面对零持股，整笔拒绝，数据库不会写入半笔。
- 同一天多笔以录入顺序为准；系统不强制 T+1，只保证不会卖出超过持有。需要时先录买入再录卖出。

## 5. 分红、送股的调整

台账不会自动同步除权除息，需要你按券商的实际到账情况手动录一笔调整：

- **送转股**（例如 10 送 5，持有 900 股）：方向选"送转"，数量填新增的 450 股，价格留 0。股数增加、总成本不变，均价被摊薄。
- **现金分红**：方向选"分红"，数量填登记日持股数，价格填每股**税后**到账现金，费用填红利税等扣款（没有就留空，分红不估算费用）。
- 分红**单列**为"现金分红"，**不冲减成本**：总盈亏 = 浮动盈亏 + 已实现盈亏 + 现金分红。这样成本只由真实买入费用决定，更保守，也更容易与账单核对；代价是均价可能与券商显示的"成本价"（常含分红冲减）不一致。
- 配股可按一笔买入记录；缩股（并股）暂不支持。

## 6. 隐私边界

持仓是私人财务信息，下表是已落实的做法：

| 出口 | 做法 |
|---|---|
| 访问 | 仅可信本机；必须带网站会话 cookie 与 `X-Requested-With: dashboard`（GET 也要）；POST 还检查 Origin。外部地址、代理/隧道头、`trycloudflare` 域名、分享口令一律得到 404，分享口令不能换取持仓访问 |
| 存储 | 固定为 `data/holdings.db`（`data/*` 已被 git 忽略）；导入模块、读空库都不创建文件，第一次写入才创建，权限 0600，拒绝符号链接和非普通文件 |
| 日志与审计 | 持仓代码不使用 `print` / `logging`；库内 `audit` 表只记动作（新增 / 撤销 / 设置总资金）和流水号、时间，不记代码、数量、价格、金额；不写 `data/admin_audit.jsonl`；错误响应只有固定错误码和固定中文提示 |
| 导出与分享 | 离线整站导出、分享页面、通知文本、信号的 CSV / XLSX 都不含持仓；管理后台的备份白名单不含 `data/holdings.db` |
| 联网 | 持仓代码不发起任何网络请求，价格只读本地日线缓存 |
| 浏览器 | 数据只在页面内存里，不写 localStorage / sessionStorage / IndexedDB / cookie；离开持仓页即清空；响应 `Cache-Control: no-store` |
| 测试 | 全部用临时目录和合成数据，不读写真实 `data/` |

**没有覆盖的威胁**：任何拿到网站令牌 cookie 的本机浏览器（有效期 1 年）都能看到持仓；本机被入侵；磁盘镜像或 Time Machine 备份会包含 `data/holdings.db`。如果担心，可以后续加"持仓页二次口令"，本任务没有做。

## 7. 备份建议

- **备份**：关闭网页后复制 `data/holdings.db` 到安全位置即可（它是单个 sqlite 文件，`journal_mode=DELETE`，没有 `-wal` / `-shm` 侧文件）。例如：

  ```sh
  cp -p data/holdings.db ~/Backups/holdings_$(date +%Y%m%d).db
  ```

- 备份文件同样是私人财务信息：不要放进仓库、网盘公开目录或聊天工具；权限保持仅自己可读（`chmod 600`）。
- **恢复**：停止服务，把备份文件覆盖回 `data/holdings.db`，确认权限为 0600（程序下次写入时也会自动收紧）。不要用符号链接指向别处，会被拒绝。
- 管理后台自带的备份**不会**包含持仓库，这是有意设计，所以必须自己复制。

## 8. 信号页联动

个人模式下进入信号页，页面会读一次 `GET /api/holdings`（只在浏览器内存里用，不写入信号数据，也不进 CSV / XLSX 导出）：

- 卖出 / 减仓信号且你持有：置顶（原排序不变）、浅橙底色，并标注持有股数、成本、持有天数、浮动盈亏。
- 卖出 / 减仓信号但未持有：整行降权变淡，标注"未持有"。
- 买入 / 加仓信号且已持有：标注"已持有"，不重排。
- 台账为空或读取失败（网络、401、404、500）时**不做任何标注**，只显示横幅提示，不会把信号误标成"未持有"。
- 离开信号页即清空内存里的持仓摘要。盯盘盈亏接口尚未接入，横幅只是占位。

## 9. 已知局限

- **不是券商对账单**：只记录你手动输入的内容；漏录、录错都会让结果偏离真实账户。定期与券商持仓核对。
- 现价来自日线缓存的收盘价，不是实时价，可能缺失或偏旧；"价格偏旧"用"价格日期距今超过 5 个自然日"近似"旧于 3 个交易日"（没有交易日历），长假后可能偶发误提示。
- 费用估算用的费率尚未与真实账户核对，估算值会标"估算"。
- 不支持北交所、可转债、港股通、美股、融资融券；缩股暂不支持，配股按买入记录。
- 总资金是你手填的"账户总资产（含现金）"，不会随盈亏自动调整，占比仅供参考。
- 盯盘（实时盈亏）尚未接入，页面只有占位说明。
- 信号页与持仓的只读联动已实现（见第 8 节），但**今日页没有联动**（今日页只显示条数，没有逐股行）；联动依赖日线缓存价格，不是实时盈亏。
- 手机宽度、深浅色、中英文的页面外观**没有在真实浏览器里验收**，需要你自己目视确认。
- 单用户设计：同一时间只有一个写入者；写入每分钟最多 60 次。
- 这是记录工具，不构成投资建议；浮盈亏的数字不能说明策略有效，也不代表未来收益。
