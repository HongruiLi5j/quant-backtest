# 夜间大数据分析（T006 S3d）使用说明

两个互相独立、**不用 AI、不联网**的脚本，适合睡觉时跑。都只读本地数据，输出写到你指定的新位置，**拒绝覆盖**已有输出。

| 脚本 | 作用 | 预计时间（单线程） |
|---|---|---|
| `scripts/run_factor_scan.py` | 全市场历史因子扫描：24 个因子对未来 20 日收益的 IC / 单调性 / 高低分组差 | 全市场 2024-01 到封存段前约 2–4 小时 |
| `scripts/signal_backfill.py` | 信号账本里过去 N 天的信号，查之后 1/3/5/20 日真实收益并汇总 | 约 30 分钟（大头是读 5000+ 个日线文件） |

## 1. run_factor_scan.py

```
python3 -B scripts/run_factor_scan.py --start 2024-01-01 --end 2026-10-22 --output data/market_monitor_intraday/factor_history/
```

- `--end` 晚于 2026-03-31 时**自动截到 2026-03-31** 并打印警告：2026-04-01 起是封存（锁定测试）段，不能作为扫描/筛选用的训练数据，这段日线也不会被读入内存，所以标签不会偷看它。`--start` 落在封存段会直接拒绝。
- 每 100 个评估日（`--chunk-days` 可改）把中间结果写到 `<output>/checkpoints/chunk_NNNNN.parquet`，stdout 打印进度条。**被中断（Ctrl-C、合盖休眠）后，用完全相同的命令再跑一遍就会续跑**；参数变了会报“断点与本次参数不一致”，需要换新目录。
- 输出目录已有最终结果、或是别的非空目录，直接拒绝（退出码 2）。想重跑请换一个目录（旧的由你自己决定是否清理）。
- Mac 睡眠会中断运行：夜里跑请接电源并用 `caffeinate -i` 包一下，或醒来后重新执行同一命令续跑。
- 产出：
  - `factor_history_summary.csv`：每个因子一行的汇总；
  - `factor_history_daily.parquet`：逐日逐因子的 IC、有效股票数、10 组平均收益 g1..g10、高-低差 tmb、触发股票数、触发组平均收益；
  - `report.md`：可读报告（按 IC 的 Newey-West t 排序）。

### 标签怎么定义
信号日 t 收盘后出信号 → t+1 开盘买 → t+20 收盘卖，`close[t+20]/open[t+1]-1`，与信号账本口径一致，没有用 t 日之后的信息做因子。最后 20 个评估日没有完整未来，IC 为空，不参与汇总。

### 怎么读 factor_history_summary.csv
`ic_mean / mono_rho / tmb_mean` **已乘以因子方向**（direction，+1 越大越好，-1 越小越好），所以正数 = 因子按自己声明的方向有效；`ic_mean_raw` 是没乘方向的原始值。

| 列 | 含义 | 判断 |
|---|---|---|
| `ic_mean` / `ic_std` | 每日 Spearman 秩相关的均值 / 标准差 | 均值常在 0.02–0.05 就算有用；看符号和稳定性 |
| `ic_t` | 朴素 t = 均值/(标准差/√n) | **会被高估**：20 日收益窗口相邻日重叠，IC 序列强自相关 |
| `ic_t_nw` | Newey-West(滞后 19) 校正后的 t | **以它为准：> 2 才算 IC 显著**（`ic_ok`） |
| `mono_rho` | 10 组“日均未来收益”对组号的秩相关（已乘方向） | **> 0.7 才算单调**（`mono_ok`）；flag/filter 因子没有十分组，此列为空 |
| `tmb_mean` / `tmb_t_nw` | 最高 10% 组 − 最低 10% 组的未来 20 日平均收益，及其 NW t | 差为正且 `tmb_t_nw` > 2 才算显著（`tmb_ok`）；flag/filter 因子是“触发 − 未触发” |
| `passes_all` | `ic_ok` 且（单调或非 score）且 `tmb_ok` | 只是历史上的描述性通过 |
| `passes_bonferroni` | `ic_t_nw` > 2.87（24 个因子、双侧 5%） | 同时看 24 个因子的多重检验门槛，比 2 严格 |
| `avg_n_trigger` / `trig_ret_mean` | 每天触发股票数 / 触发组平均未来收益 | 触发数太少说明结论不稳 |

### 重要提醒
- “通过”不等于有 Alpha：没扣费用、没处理涨停买不进/跌停卖不出、同一时段的因子互相相关；要升级为策略必须走 `docs/validation_howto.md`（样本外、成本翻倍、多重检验校正）。
- 大概率会出现“碰巧显著”的因子：24 个一起看，纯噪声里平均也会有 1 个 |t|>2。

## 2. signal_backfill.py

```
python3 -B scripts/signal_backfill.py --days 90 --output data/market_monitor_intraday/signal_backfill.csv
```

- 以只读模式（SQLite `mode=ro`）打开 `data/signal_ledger.db`，**不建表、不写入**；`--ledger` 可指向别的账本，`--asof` 指定“今天”（默认今天），`--cost-bp` 改往返费用（默认 30bp）。
- 三个输出文件都要求不存在，否则拒绝（退出码 2）：`signal_backfill.csv`（逐条信号 → 各期收益）、`signal_backfill_summary.csv`（汇总）、`signal_backfill_report.md`（报告）。
- 收益口径：信号日 D 的下一交易日开盘入场，D+h 个交易日收盘出场（h = 1/3/5/20）。h 还没走完的新信号对应列留空，不参与统计。账本为空或没有 signals 表时不报错，只写空文件和一句说明。

### 怎么读 signal_backfill.csv 和汇总
- 逐条文件：`ret_h` 是该股票的收益，`mkt_h` 是同一天同口径下**全市场所有股票的平均收益**（随机挑一只的期望）；`direction` 买入/加仓为 +1，卖出/减仓为 −1。
- 汇总表（按策略 × 动作 × 持有期，另有“全部”行）：
  - `mean_ret`：原始平均收益；`mean_adj`：方向调整后（正数 = 方向猜对，卖出/减仓是“避开的跌幅”）；`mean_net`：买入/加仓扣费用后；
  - `win_rate`：方向调整后收益 > 0 的比例；先看 **blend2 整体（动作=全部）的胜率**，再看四个动作的分布是否一致；
  - `mean_excess` 与 `mean_mkt`：和“随机挑一只”的差距。超额接近 0 说明信号和随机没区别——大盘整体上涨时所有买入都会显得“对”，必须看超额；
  - `vs_blend2_adj`：该行方向调整后收益减去 blend2 整体的同一持有期值；
  - `small_sample`：n < 30，只展示，不作结论。同一天的信号共享同一个大盘行情，不是独立样本，要同时看 `n_days`（至少几十个信号日才算数；目前账本信号日很少）。

## 3. 已知局限
- **幸存者偏差**：本地日线只有当前还在交易的股票，退市股没有处理，历史收益会偏乐观。
- **分钟级冲击未计**：用日线开盘/收盘价成交，没有滑点、冲击成本、涨停买不进、跌停卖不出、停牌。
- **费用用保守默认**：信号回填默认往返 30bp（账本里是 16bp）；因子扫描**完全没扣费用**。
- 后复权价：`close×volume` 只是成交额近似（见 `docs/factors_library.md`）；ST 状态来自当前名称快照。
- 因子扫描只用 2026-03-31 以前的数据；封存段不用于筛选。信号回填评估的是已记录的真实信号，不属于“筛选训练”，但它读到的日线可能包含封存段之后的日期，结论只作复盘参考。

## 4. 和 run_eod_analysis.py 的关系
- S3c 的 `run_eod_analysis.py` 是**当日**的：收盘后给监控名单跑 24 个因子、判断市场状态、残差排名。
- S3d 是**历史**的：回看这 24 个因子过去在全市场有没有预测力、过去的信号准不准。它只调用 `src/market_monitor/factors.py`，不改 S3c 的任何文件。
- 用法上：先用本文件的扫描结果知道哪些因子历史上相对靠谱，再看每天的 EOD 报告里它们的触发情况；但 EOD 的结论仍然只是复盘参考。
