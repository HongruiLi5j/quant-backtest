# 逐日回放学习使用说明(T008)

> 状态:S0–S6 已完成。设计见 handoff/reports/T008_plan.md(该目录不进公开仓库)。
> 这是离线研究工具:不接网站、不联网、不改 `app.py` / `daily.py` / `backtest.py`,不下单,不构成投资建议。
> **回放结果好不代表策略有效。** 请先读第 6 节(局限)再看任何数字。

## 1. 它解决什么问题
PDF 的思路是:不要只相信一次回测,而是把历史当成"一天一天重新发生",每天只用当天收盘及以前的数据做预测,第二天核对,看准确率曲线和置信区间。T008 把这个流程做成可复现的离线工具:

1. 100 个候选策略(含 5 个随机对照)登记在 `src/replay/strategies_catalog.json`,带校验和哈希,试验记录必须写下哈希。
2. 因子向量化计算,并有"未来函数断言":截断到 T 日重算,T 日的值必须与全量计算一致。
3. 单因子分组单调性检验(未来 20 日收益),不单调的直接淘汰。
4. 逐日回放:T 日收盘出信号,T+1 开盘成交,扣 A 股成本。
5. 训练段一次性淘汰(规则先写死),验证段只看不调,封存段只在最后用一次。
6. 幸存者做投票/在线加权组合,叠加市场状态过滤和风控上限。

## 2. 模块一览
| 文件 | 作用 | 阶段 |

| `src/replay/engine.py` | 逐日回放引擎、成交约束、落盘(sqlite) | S3 |
| `src/replay/selection.py` | 训练段淘汰、验证段只看、封存段守卫、冻结文件 | S4 |
| `src/replay/ensemble.py` | 幸存者投票/加权组合、市场状态过滤、风控上限 | S5 |
| `scripts/replay_run.py` | 把 S1–S5 串起来的命令行 | S5 |

依赖:`registry.py` 只用标准库;其余用 pandas / numpy(`.venv` 已有)。

## 3. 怎么跑
**先 dry-run**(默认就是 dry-run:只校验清单、日期、参数和输出目录,打印计划,不读行情、不写文件):

    .venv/bin/python -B scripts/replay_run.py --start 2024-01-01 --end 2026-03-31 --universe 500 --out /tmp/replay_run_01

输出里要核对的几项:`catalog_hash`、`n_grid_combos`(非对照策略的网格组合,当前清单 1.1 为 485)、`m_trials`(多重检验用的 m,当前 490,含对照)、`segments`(三段日期)。

**小范围试跑**(先挑几个策略,确认流程通):

    .venv/bin/python -B scripts/replay_run.py --start 2024-01-01 --end 2026-03-31 --universe 200 --strategies brk_01,brk_02 --out /tmp/replay_run_02 --execute

(策略 ID 以清单为准,可用 `.venv/bin/python -c "from src.replay import factors; print(factors.scorable_ids())"` 列出。)

**完整回放**(由所有者手动启动,数小时级;不要放进接力或定时任务):

    .venv/bin/python -B scripts/replay_run.py --start 2024-01-01 --end 2026-03-31 --universe 500 --out /新目录 --execute

常用参数:

| 参数 | 含义 |
|---|---|
| `--universe N` | 股票池 = 起点之前成交额排名前 N 只(用起点前的数据排名,避免用未来信息选股票池) |
| `--top-n` | 每个策略每天取前几只作为次日持仓,默认 20 |
| `--null-k` | 随机对照零分布抽样次数,默认 1000;见第 5 节"p 值下限" |
| `--n-boot` | 单调性检验的 bootstrap 次数 |
| `--seed` | 随机种子;淘汰时的 seed 与 null_k 会被冻结,之后改不了 |
| `--strategies` | 逗号分隔的策略 ID,默认全部非对照策略 |
| `--industry-json` | 行业映射(行业动量类策略用);不给则这类策略无法判定 |

硬性约束(脚本会拒绝违规):
- 输出目录必须不存在或为空,不能在 `data/` 或行情目录里面,拒绝覆盖。
- `--end` 不得晚于验证段末(2026-03-31)。封存段(2026-04-01 起)在这里没有入口。
- 北京时间 15:30 前的当天 K 线丢弃;行情只读。
- 淘汰/幸存冻结文件和试验账本在 `handoff/data/replay/`:**同一份清单只能淘汰一次**,重跑读冻结结果,不会"换个 seed 再来一次"。

## 4. 怎么读报告(`report.md`)
报告第一行是红线提示:"存在幸存者偏差/状态未过滤"。按下面顺序读:

1. **清单哈希与区间**:确认哈希与 dry-run 一致,股票池大小、`seed`、`null_k` 对不对。
2. **单调性(训练段)**:检验了多少策略、多少参数组合通过。通过只是"入场券",不是有效证据。
3. **训练段淘汰**:幸存/淘汰/无法判定的数量,以及 Holm 的 m。淘汰规则(写死,不得放宽):
   - 扣成本后的周均超额低于随机对照零分布的第 5 百分位;
   - 月换手 >100%,或成本前年化超额 >0 而成本后 ≤0;
   - 训练段内有持仓的交易日占比 <50%;
   - 单调性未通过。
   淘汰者**仍计入试验次数**(m 不减),也不允许因为验证段结果而回头改。
4. **验证段(只看不调)**,每个幸存者看这几项:
   - 周均净超额与经验 p、**Holm 校正后的 p**(m = 网格组合总数,不是 100);
   - **成本翻倍**后是否仍为正;
   - **月换手**(≤100% 才合格);
   - **参数邻域**:相邻网格档位也要盈利,否则是"参数孤岛",视为过拟合;
   - 是否优于**随机对照**。
5. **组合与市场状态过滤**:投票/加权两种组合的"满仓不过滤"版本用来判断选股质量(显著性只对它做);风控后的 managed 版本看收益、波动、最大回撤、换手、降仓天数占比。波动率阈值取自训练段 80 分位并冻结。
6. **入影子池条件**:验证段扣成本后超额 > 随机对照、月换手 ≤100%、参数邻域也盈利。**满足只意味着进入影子观察,不是策略有效的证据,更不会自动成为主策略。**
7. **局限**(报告末尾):五类局限,见下一节。

输出目录里的文件:`report.md`(人读)、`run_meta.json`、`monotonic_report.json`、`train_record.json`、`valid_report.json`、`ensemble_report.json`、`replay.sqlite`(逐日逐策略的预测与结果)。JSON 写入后不覆盖。

## 5. 几个容易误读的点
- **p 值下限卡住显著性**:经验 p 的最小值是 1/(null_k+1)。m≈492 时,null_k=1000 意味着 Holm 后**不可能**显著(报告里有 `empirical_p_floor_blocks_holm` 提示)。想让显著性检验有意义,null_k 需要上万(约 9800 以上),代价是算得更慢。建议先 1000 跑通流程,再决定是否加大。
- **20 日标签重叠**:相邻两天的未来 20 日收益共享 19 天,按日当独立样本会高估显著性,所以单调性按块 bootstrap(块长 ≥20),评估按周聚合。
- **禁运**:训练段末 20 个交易日的标签会越界进入验证段,这些样本在训练段评估时丢弃。
- **不翻转信号**:策略效果为负就是淘汰,不允许"反着买"——那是事后选方向,等于多一次隐形试验。
- **封存段看过即污染**:只走 `LockedTestGuard` 和固定位置的账本,同一股票池/同一策略的封存段不能看第二次。

## 6. 局限(必须随结果一起报告)
1. **过拟合**:约 490 个网格组合里挑幸存者,训练段表现是样本内的;组合方式、半衰期、`top_n` 也是看过幸存者后新增的自由度,已计为额外试验,但仍是自由度。
2. **多重检验**:Holm 的 m = 清单网格组合总数(+ 组合变体数),淘汰者不扣除;经验 p 下限受 `null_k` 限制。
3. **样本量**:验证段约 9 个月、约 40 周,置信区间很宽;20 日标签重叠;A 股 2024–2026 本身只是一两种市场环境。
4. **交易成本**:费率默认值是占位值,**需所有者按实际券商费率核对**;最低佣金在组合层面被忽略;涨跌停/停牌在没有时点状态表时用 ±9.9% 近似;滑点是保守估计,不是实测。
5. **幸存者偏差**:股票池来自"现存股票"的日线缓存,已退市的股票不在里面;没有时点状态表(ST / 次新 / 退市)过滤(T010 的状态表接入后才能改善)。这会让历史表现**系统性偏好**,尤其是反转、低价、低成交额类策略。

另外:
- 组合成本按目标权重变化估算,忽略持仓漂移;卖不出的情形不模拟。
- 幸存者只有一两个时,投票与加权几乎相同,无法比较两种方式优劣。
- 回放只能让策略**进入影子池**。成为主策略仍要在真实前向信号上过 `promotion` 的门槛(≥12 个完整交易周、≥500 条走满信号、连续 4 个周检查点通过 Holm、相对现任优势、现任满 12 周),并且策略公式层的改动只生成建议,等所有者人工批准。

## 7. 面试讲法(要点)
- 为什么 m 取网格组合总数而不是 100:每个参数组合都是一次"尝试",多重检验的惩罚要对应尝试次数。
- 为什么停止规则要先写死:规则在看到验证段结果之前确定,才不会变成"挑到好结果为止"。
- 为什么随机对照用"匹配抽样"(保持当日选股条数不变,在可交易股票里随机抽):排除"只是选股数量/换手不同"造成的差异。
- 为什么用 T+1 开盘价而不是 T 日收盘价成交:信号用到了 T 日收盘价,收盘后无法以该价成交。
- 为什么市场状态指数不用回放行里的 `mkt` 字段:`mkt[T]` 是 T+1 开盘到 T+2 开盘的收益,在 T 日是未来数据。
