# A 股实时行情 provider 升级:使用说明(T016 S4)

本文说明盯盘页新增的三个配置项:**数据源(provider)**、**名单上限(max_watch)**、**批量模式(batch_mode)**。
设计背景见 `docs/providers_upgrade_plan.md`;盯盘本身的用法见 `docs/market_monitor_howto.md`。

## 1. 是什么

| 配置 | 取值 | 含义 |
|---|---|---|
| 数据源 provider | `tencent` / `easy` | `tencent`:原来的腾讯单接口,逐只请求(每只最短 60 秒、相邻请求隔 10 秒、一次 5 只)。`easy`:easyquotation 批量模式,整个名单一次请求(新浪 + 腾讯双源,允许部分成功)。 |
| 名单上限 max_watch | 整数 1–5500 | 监控名单(持仓 + 自选 + 信号股)最多多少只,超出会截断并在状态里提示。默认 500。 |
| 批量模式 batch_mode | 开 / 关 | 与 provider 是同一件事的两种写法:开 = `easy`,关 = `tencent`。页面上两个控件互相联动,不会出现矛盾。 |

另外两项随模式变化:
- 采样间隔下限:逐只模式 30 秒,批量模式 10 秒(等于后端 `BATCH_MIN_INTERVAL`,低于 10 页面和后端都会拒绝;大名单还会按名单大小自动抬高有效间隔)。
- 信号前 N 只(top_n)的上界等于当前 max_watch。

## 2. 怎么切换

1. 个人模式下打开「盯盘」页,找到「控制」卡片里的配置表单。
2. 在「数据源」下拉里选 `easy`(批量模式开关会自动勾上),需要的话改「名单上限」,点「保存配置」。
3. 修改在下一轮采集生效;状态行和 `/api/market_monitor/quotes` 里的 `status.provider` 显示当前实际生效的数据源。
4. 页面只会提交**和你上次请求值不同**的数据源字段(比较的是你请求的数据源,不是当前实际生效的)。因此批量模式因故障被自动降级后,你只改采样间隔不会把批量设置悄悄改掉;而降级后你主动选 `tencent` 会被真正提交。

前提:本机已安装 easyquotation(`PYTHONPATH` 里能找到)。没装时,选 `easy` 会被拒绝,或启动时自动退回 `tencent`。
安装第三方依赖需要你自己决定(见方案文档 D2),本文不替你装。

## 3. 新手测试建议:先 10 只,稳定再放开

1. 先保持 `tencent`,确认盯盘本身正常。
2. 把名单上限设为 **10**,数据源切到 `easy`,采样间隔用 30 秒以上,只在交易时段开始盯盘。
3. 观察一两个交易日:报价时间在更新、状态行没有暂停、`missing`(缺失)比例低、成交量没有出现单位错乱的告警。
4. 稳定后按 10 → 50 → 100 → 500 逐级放大,每级都观察一个交易日再往上;不要一次跳到 5500。
5. 方案文档建议首次真实验证 ≤100 只、间隔 ≥30 秒;成交量单位(手/股)在真实验证里一并核实。

## 4. 风险

- **被封 IP**:新浪、腾讯都按 IP 限流/封禁,封的是整台电脑的这类访问,不只是本程序。批量模式请求次数少,但名单越大单次越重;所以默认名单上限 500、默认间隔 60 秒(建议新手测试时用 30 秒以上),遇到 403/429 会立刻暂停且不重试。
- **许可条款**:这些是网页行情接口,没有官方 API 授权;批量高频更接近"爬取"。本项目只用于个人自用,不转发、不公开数据、不保存上游原文。使用前请自行评估服务条款。
- **不伪装**:新 provider 与原 TencentProvider 一致,不发 Cookie / Referer / User-Agent 伪装头;速率上限均可配置且有硬下限。
- **数据质量**:上游改版或库停更可能解析出错;解析结果仍经过原有的时间、成交量等校验,缺失过多算一次失败。批量模式下连续 3 次失败先自动降级为逐只(tencent);逐只模式下再连续失败 3 次才暂停(见 §5)。
- 行情仅供观察,不接任何券商接口,不会自动下单。

## 5. 如何从 easy 回滚到 tencent

- 页面:数据源改回 `tencent`(批量模式自动取消),保存配置。下一轮起恢复逐只请求。
- **先把采样间隔调到 30 秒以上并保存,再切数据源**。后端切换时先用旧间隔按新模式校验,批量模式下若间隔还是 10 秒这类小于 30 的值,一次同时改间隔和数据源会被拒绝。页面已自动拆成两步(先存间隔、再切数据源),但如果你用其他方式调接口,请自己按这个顺序。注意:两步是依次提交的,如果第二步(切数据源)失败,第一步的间隔**已经生效**(间隔改成了 30 秒以上,但数据源还是 easy);页面只会显示错误,请重新检查后再保存一次。
- 不需要迁移数据,也不需要改代码:`TencentProvider` 与原有逻辑一行未改,始终作为兜底。
- 批量模式连续整批失败 3 次时程序会自动降级为 tencent。**降级只在本次运行内有效**:你点「停止」后再「开始」(重新开始),降级状态会被清除,又会回到 `easy`。所以要永久回滚,必须在页面把数据源选成 `tencent` 并保存(降级期间下拉框仍显示你请求的 `easy`,状态区会提示「已自动降级」;选 `tencent` 再保存才会真正提交)。想重试 `easy`,停止后重新开始即可。
- 没装 easyquotation 时,默认的批量请求会退回 tencent,状态区会提示「已请求批量模式,但本机没有安装 easyquotation」;此时选 `easy` 保存会被拒绝,页面显示固定提示,数据源保持不变。这种状态下实际在用 tencent,下拉框也显示 `tencent`(只有“自动降级”时下拉框才继续显示你请求的 `easy`),保存时不会重复提交数据源;状态区的“未安装”提示会一直在,直到装好 easyquotation 或重启服务。
- 名单上限回滚:可以保留,也可以改回 60(原默认);超过 60 只时逐只模式一轮会很慢(60 只约 10 分钟),建议同时调小。

## 5b. 老用户迁移须知(必读)

- **设置只存在内存里**:数据源、名单上限、批量模式、采样间隔都不写配置文件。重启网站服务(或 Python 进程)后全部恢复为程序默认值,需要在页面重新设置。设计文档原先设想把 MAX_WATCH 放在本机配置文件里,实际没有做。
- **默认值变了**:现在调度器默认 `batch_mode=True`、`max_watch=500`(以前是逐只、上限 60)。也就是说,一旦本机装上 easyquotation,重启后会在你不知情的情况下直接用批量模式盯 500 只。没装 easyquotation 时才会退回 tencent(并在状态区提示)。如果你想保持老行为,装好后第一件事是到页面选 `tencent`、把名单上限改回 60 并保存,再开始盯盘。
- 以上两点是 S2/S3 的决定,S4 不改后端,只在这里写清楚;是否改成"默认逐只"或"持久化设置",需要所有者另行决定。

## 6. 与现有 S1–S3b 的关系

- **S1**(`providers_easy.py`):批量 provider 本身(easyquotation 解析、拆批、双源、间隔与请求数限制)。
- **S2**(`watchlist.py` / `scheduler.py`):max_watch 可配置、调度器批量模式、降级逻辑。
- **S3 / S3b**(`wiring.py` / `scheduler.set_runtime`):HTTP 接口 `/api/market_monitor/config` 接受 `provider`、`max_watch`、`batch_mode`,仅本机、先全部校验再落地、失败不改状态。
- **S4**(本阶段):只做前端表单、中英文案和本文档,不改后端。表单提交的字段与 S3 的校验规则一一对应,非法输入由服务端拒绝并显示固定的提示文案。
