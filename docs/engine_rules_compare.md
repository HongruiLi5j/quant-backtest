# 三引擎策略规则对照表（C09）

对照对象：`src/strategies.py`（自研）、`engines/bt_strategies.py`（backtrader）、`engines/rq_strategies.py`（RQAlpha），
以及它们各自的执行底座 `src/portfolio.py`、`engines/bt_base.py`、`engines/rq_base.py`，和参数登记表 `src/registry.py`。
核对方式：逐行读代码（静态） + `scripts/engine_rule_diff.py` 在合成行情上实测（动态）。
回归护栏：`PYTHONPATH=.engines_lib .venv/bin/python tests/test_engine_rules.py`。

**结论一句话：7 个策略的入场、出场、参数默认值、仓位公式在三份代码里逐条一致，没有发现规则写法不同；**
差异都在「实现细节」层面（指标起算、浮点并列、预热期、执行底座），下面第 3、4 节列全。

## 1. 逐策略规则对照

记号：`c` 当天收盘，`SMA(n)` n 日简单均线，`peak` = 入场后的最高收盘（入场当天的收盘作初值，之后逐日取 max），
`vs` = 波动率目标仓位 = min(1, 0.15 / 过去 20 日收益样本标准差×√252)。所有信号只用当天收盘及以前的数据，次日开盘成交。

| 策略 | 入场 | 出场 | 仓位 | 三处是否一致 |
|---|---|---|---|---|
| `ma_adx_original` | 未持仓 且 SMA5 上穿 SMA20 且 ADX14 > 20 | SMA5 下穿 SMA20（无止损、不看 ADX） | 满仓 1/0 | 一致（自研 `strategies.py:175-189`，bt `:87-104`，rq `:75-90`） |
| `ma_adx_plus` | 上穿 且 ADX14 > 20 且 c > SMA200 | 下穿，或 c < peak − 3×ATR14，或 c < SMA200（任一） | 持仓时 `vs`，否则 0 | 一致（`:141-172` / `:108-133` / `:94-117`） |
| `trend_vol` | c > SMA200×1.01 进；c < SMA200×0.99 出（迟滞） | 同左 | 持仓时 `vs` | 一致（`:28-52` / `:20-35`+`:137-146` / `:16-29`+`:121-126`） |
| `trend_ens` | 100/150/200/250 四条均线各自按 `trend_vol` 的迟滞规则出 0/1 | 同左 | 四个状态的平均值 × `vs` | 一致（`:55-67` / `:150-162` / `:130-139`） |
| `donchian_s1` | c > 前 20 日最高价（不含今天） | c < 前 10 日最低价（不含今天），或 c < peak − 2×ATR20 | 持仓时 `vs` | 一致（`:100-106`+`:71-97` / `:38-59`+`:166-175` / `:32-50`+`:143-149`） |
| `rsi2` | c > SMA200 且 RSI(2) < 10 | c > SMA5，或持有满 10 根（入场当根 held=0，之后每根 +1） | 满仓 1/0 | 一致（`:110-137` / `:62-83`+`:179-188` / `:53-71`+`:153-158`） |
| `blend2` | 趋势集成 + RSI2 + 海龟 S1，全部默认参数 | 各自独立 | `mix[0]×w趋势 + mix[1]×wRSI2 + mix[2]×w海龟`，`mix` = 权重/权重之和（和为 0 时三等分） | 一致（`registry.py:121-125` / `:192-210` / `:162-170`） |

## 2. 参数默认值（自动读出，不靠人眼）

`defaults_table()` 把注册表、自研函数签名、backtrader `params`、RQAlpha `__init__` 签名里的默认值并排读出：
共 58 项（策略, 参数），其中 35 项有 ≥2 个来源可以比对，**不一致 0 项**；其余 23 项只有一个来源
（bt 独有的 `limit/band/lot` ×7 = 21，自研独有的 `max_lev` ×2，都不是策略规则）。
唯一的「表面差异」是类型：注册表里写 `20`、代码里是 `20.0`，数值相等。

两处读源码补进来的（自动读不到）：自研 `donchian_s1` 的 `atr_len=20` 写死在调用里，`vol_len` 沿用 `donchian_breakout` 的默认 20；
`blend2` 的三个子策略参数写死在代码里（bt `:198-202`，rq 用各子类默认值，自研 `registry.py:125`），靠信号对照覆盖。

## 3. 执行底座对照（不是策略规则，但会让三个引擎的回测结果不同）

| 项目 | 自研 `portfolio.run_weights` | backtrader `bt_base.AShareStrategy` | RQAlpha `rq_base.build_funcs` |
|---|---|---|---|
| 成交时点 | `held = target.shift(1)`：t 收盘定、t+1 开盘成交 | `cheat_on_open` 的 `next_open` 按上次 `target` 下单、开盘价成交 | `open_auction` 按上次 `target` 下单、开盘价成交 |
| 调仓阈值 10% | `apply_band`：参照 = 上一个被接受的目标（含后来被涨跌停挡住的） | 参照 = `applied`（上次真正执行的目标） | 同 bt |
| 整手 | 无（按比例持仓） | `floor(总资产×目标/开盘价/100)×100` | 同 bt（`//100*100`） |
| 买得起多少 | 无限制 | 扣最低佣金和费率后按整手算 `afford` | 同 bt |
| 费用 | 固定单边 8bp（`config.py` cn `stock_cost_bp`） | 佣金万 2.5 + 过户费万 0.1，每笔最低 5 元；卖出印花税 2023-08-28 前 10bp、之后 5bp | RQAlpha 内置费用模型，参数调成与 bt 相同 |
| 持仓期间权重漂移 | 每天开盘免费重置回目标（`portfolio.py` 顶部注释写明的近似） | 股数不变，权重随价格漂移，直到下次越过阈值 | 同 bt |
| 涨跌停 | 开盘涨幅 ≥ 限幅 − 0.2% 买不进；跌幅同理卖不出；保持原仓位，次日再试 | 同左（`gap` 判断） | 数据里把涨跌停价设成 `prev×(1±(限幅−0.2%))±0.01`，RQAlpha 触发线 = 涨停价 − tick(0.01) + 1e-6，等价于差 1e-6 元 |
| 空仓现金 | 不计息（`inhouse.run` 里 `cash_ret=None`） | 不计息 | 不计息 |
| 参数传递 | `clean_params` 白名单 | `cls.params._getkeys()` 过滤——**不认识的参数会被悄悄丢掉** | `**params` 直接传——不认识的参数会报 `TypeError` |

## 4. 已确认的实现层差异（没有一条改变策略规则本身）

| # | 差异 | 影响面 | 实测证据（`outputs/C09/engine_rule_diff_stdout.txt`） |
|---|---|---|---|
| D1 | backtrader 的 `next()` 要等该策略里**所有**指标都有值才开始调用，所以 `trend_ens` / `blend2` 里各子状态机都从第 250 根才从零起步；自研和 RQAlpha 里每个子状态机各自更早起步 | 只影响 `trend_ens`、`blend2` 在 bt 引擎的前 ~250 根；但 10% 调仓阈值的参照仓位（`applied`）起点不同，会让后面的成交日错开，直到下次清仓才重新对齐 | 默认参数 20 个种子：两个策略的 bt 预热期（前 260 根）信号 20/20 不同；第 260 根之后 `trend_ens` 0 天不同，`blend2` 只有 D3 那一个并列价种子不同；执行层 14 次端到端里 1 次（`trend_ens` 种子 200）成交日期错开，逐日追踪：bt 开始运行的第一天（2021-06-16）`applied=0`、持股 0，而 RQAlpha 已持 3000 股、`applied=0.5529`；此外把 `trend_ens` 的迟滞区间调到注册表上限 0.05 的压力测试里，20 个种子中 1 个在区间内出现状态差异（该种子 2.26% 的天数不同） |
| D2 | backtrader 的 ATR 从第 2 根起算（缺第一根真实波幅），自研 / RQAlpha 第 1 根用 最高−最低 | 只影响起算后头 ~100 根的止损线 | ATR14：bt 晚 1 根有值，起算后前 60 根最大相对差 4.41%，第 260 根后 7.48e-10；ATR20：3.36%，第 260 根后 1.8e-07；自研 vs RQAlpha 完全相等（差 0） |
| D3 | 收盘价刚好等于均线（或两条均线刚好并列）时，三个均线实现的浮点误差不同，严格大于/小于被翻转 | 罕见；一次翻转让持仓多/少一两天 | 默认参数 20 个种子，`rsi2` 有 4 个种子出现开/关分歧、`ma_adx_original` 1 个；区间内差异天数占比：均值 ≤0.020%，最差 0.161%；种子 12 的第 442 根：收盘−SMA5，自研/bt 恰为 0，RQAlpha 为 +3.2e-14；RQAlpha 的滚动和误差最大（5 个分歧事件里，RQAlpha 的偏离在 2.1e-14 ~ 6.8e-14，自研最大 3.6e-15，bt 恰为 0） |
| D4 | 「均线先下方、然后恰好相等、再回到上方」：自研 / RQAlpha（与 AmiBroker `Cross` 同义）算一次新上穿，backtrader `CrossOver` 不算（它回看最近一次非零差） | 极罕见，要求精确并列 | 构造 5 个点的例子实测：自研 `[F,T,F,T,F]`，RQAlpha 同，bt `[nan,1,0,0,0]`；20 个合成序列里 SMA5==SMA20 共 9 天，但没有一次触发信号差异 |
| D5 | 已实现波动率恰好为 0（20 根收盘价全相同，如长期停牌填充）时：自研 `target/0=inf` 被夹到 1.0（满仓），bt / RQAlpha 写的是 `v<=0 → 0.0` | 极罕见 | 实测：自研 1.0，RQAlpha 0.0，bt 0.0 |
| D6 | bt `DonchianState` 里 `Lowest(exit_len)` 也算 minperiod：当 `exit_len > entry_len`（注册表允许，如 5 与 60）时，bt 要等 60 根才能入场，自研 / RQAlpha 5 根就能入场（此时只缺出场低点，只靠 ATR 止损） | 只在非默认参数、且只在预热期 | 静态读代码得出；随机 24 组合法参数没有触发区间内差异，没有单独构造 |
| D7 | 涨跌停挡掉一笔成交后，自研的阈值参照已经更新为被挡的目标，bt / RQAlpha 的参照仍是上次真正执行的 | 只在发生涨跌停拦截之后的几天 | 静态读代码得出；合成行情没有涨跌停，没有动态覆盖 |

## 5. 怎么复查

```
PYTHONPATH=.engines_lib .venv/bin/python -B tests/test_engine_rules.py
PYTHONPATH=.engines_lib .venv/bin/python -B scripts/engine_rule_diff.py --out-dir /某个目录
```
第一条是 pass/fail 护栏（参数默认值全一致、信号差异天数占比 ≤ 0.5%、指标相对差在上界内）；
第二条是完整实测（20 个种子 + 随机参数 + 预热压力 + 边界情形 + 端到端），约 1 分钟。
合成行情不读 `data/`、不联网；RQAlpha 的交易日历用临时文件。
