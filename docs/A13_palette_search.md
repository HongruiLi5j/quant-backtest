# A13 命令面板股票搜索：匹配规则与拼音首字母方案

## 现在的匹配方式

输入框每次变化后（180ms 防抖）请求 `GET /api/search?market=cn&q=<输入>`，服务端（`app.py` 的 `search()`）按下面的规则找，最多返回 15 条：

| 数据来源 | 服务端规则 |
|---|---|
| ETF（`config` 里的 universe） | 代码包含（不分大小写）或名称包含 |
| 自选股 | 代码包含或名称包含 |
| 全市场清单 `cn_all_list.csv` | **代码前缀**或名称包含，最多 15 条 |

返回的每行只有 `code` / `name` / `kind`，**没有拼音字段**。

前端（`shared/command-palette.js`）原来直接取返回的前 8 条。因为服务端是"ETF → 自选 → 全市场"的拼接顺序，输入 `300` 时 `510300` 这种"代码里包含 300"的 ETF 会排在 `300xxx` 前面并占掉名额。

页面条目、操作条目（切换主题等）仍是本地过滤：名称包含或链接包含输入，不变。

## A13 改了什么

- 新增纯函数模块 `shared/palette-match.js`：`rankStocks(query, rows, limit)` 把服务端返回的行按档位稳定排序再截断。
  档位：代码完全相等 → 代码前缀 → 名称包含 → 代码包含 → 其它。同档保持服务端顺序。
- 只排序，不过滤（不丢行）：服务端已经决定了谁算命中。
- 先排序、再截断：服务端返回 15 条，前缀命中如果排在第 9 条以后，原来的 `slice(0, 8)` 会直接丢掉它。
- 查询做 NFKC 归一化（全角 `６００` 视同 `600`）、不分大小写，仅用于前端排序；发给服务端的请求没改。

## 拼音首字母（gzmt → 贵州茅台）：为什么没做，怎么补

数据里没有拼音字段，前端不联网、不加第三方库，所以前端本身无法从汉字得到拼音。要做需要后端配合：

1. 后端生成拼音首字母：在生成 `cn_all_list.csv` 的地方（`src/allmarket.py`）加一列 `pinyin`，例如 `贵州茅台 → gzmt`。
   生成方式需要站主定：用 pypinyin（需新增依赖）或一次性离线生成一张静态对照表。
2. `app.py` 的 `search()`：全市场清单增加 `df["pinyin"].str.startswith(text.lower())` 的命中；返回行里带上 `pinyin`。
3. 前端：`stockRank` 在"代码前缀"之后加一档"拼音首字母前缀"（约 3 行），并把 `tests/test_palette_match_a13.py` 里 `test_pinyin_not_supported_yet` 改成正向断言。

第 2 步不做的话，输入 `gzmt` 时服务端根本不会返回贵州茅台，前端排序也无从谈起；所以拼音必须服务端先支持。
