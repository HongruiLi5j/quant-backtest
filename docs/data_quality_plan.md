# 数据质量补强计划(设计阶段)

> 状态:第 1–3 步的离线模块与测试已写好(`src/dataquality/`、`scripts/data_quality_report.py`),**尚未接入每日任务或回测**;第 4 步的接入提案已写成(见第 7 节摘要)。这份文档说明 A 股数据现在缺什么、打算怎么在不动现有每日流程的前提下补强。外部数据源和制度日期均未联网核实,标 **[需核实]** 处不要当作结论。

## 1. 为什么要做
当前 A 股全市场数据有三个会让回测偏乐观的缺口:

1. **幸存者偏差**:只有今天还在市的股票;退市股的行情没有进入回测。
2. **ST 判断是事后的**:用"今天的名字"把整段历史上的 ST 股剔除,既丢掉了这些股票正常交易的年份,也没有处理"曾经 ST、现在摘帽"的股票。
3. **没有时点状态**:某一天哪些股票已上市、已退市、停牌、处于 ST,没有任何记录;停牌名单只保留最近 60 天。

此外,后复权价由多个来源拼接而成,目前没有任何复权一致性与异常跳变检查,也没有数据质量日报。

## 2. 做什么(四步)
| 步骤 | 内容 | 位置 |
|---|---|---|
| 1 | **时点状态表**:给定股票清单、交易日历、停牌名单、可选的 ST 区间与退市日,生成每只股票每天的 `listed / listed_days / delisted / is_st / suspended / tradable`。缺信息写 `None`,**不伪造**,并统计缺失率 | `src/dataquality/status_table.py` |
| 2 | **一致性与异常检查**:坏 K 线(高<低、价≤0)、中间缺失交易日、超出涨跌幅的跳变(排除除权日与新股前几日)、零成交量但价格变动、复权因子单调性。阈值可配置 | `src/dataquality/consistency.py` |
| 3 | **每日数据质量日报**:只读数据目录,可抽样,输出 Markdown + JSON,与前一日对比;单个文件损坏不中断,整体失败只记录 | `src/dataquality/report.py`、`scripts/data_quality_report.py` |
| 4 | **接入提案**:日报如何作为每日任务之后的独立步骤运行;回测如何读取状态表过滤。只写提案,不改现有代码 | 提案文档 |

## 3. 边界(硬约束)
- 不修改任何已有行情文件(parquet)、股票列表、停牌记录。
- 不修改 `allmarket.py` 的每日更新流程,不修改 `daily.py`、`backtest.py`。
- 新功能是独立脚本,失败不影响每日更新;全程不联网(不触发东方财富快照)。
- 测试只使用合成数据与临时目录。
- 退市股历史行情的真实回补**不在本计划内**,需先确定数据来源并单独批准。

## 4. 数据来源(候选,未验证)
时点状态与退市股需要外部数据。候选包括:交易所官网退市名单(项目已有抓取函数,尚未运行过)、BaoStock(日线可能带逐日 ST/停牌标记)、新浪/腾讯日线(能否返回退市股需实测)、Tushare(历史简称变更可还原 ST 区间,需要账号凭证与积分)、RQAlpha 数据包(项目已装该引擎)、交易所公告(权威但需人工抽样核对)。另有零许可风险的做法:**从现在起自建前向记录**(每天追加名字与停牌名单),但无法回溯过去。每个来源的字段、许可与稳定性顾虑都需要先核实,再决定是否使用。

## 5. 验收
- 状态表:覆盖上市不满一年、停牌、退市、信息缺失、ST 区间边界等合成用例,缺失时为 `None`。
- 一致性检查:每类问题有合成用例;除权日、涨跌幅以内的正常波动不误报;结果对整体乘常数不变(拼接时会按常数重新对齐复权基准)。
- 日报:空目录、损坏文件、抽样都能正常出报告;测试前后数据目录文件的哈希不变。
- 日报连续 5 天正常产出后,才讨论是否接入每日任务。

## 6. 需要明确的局限
- 这套东西让我们**看见**数据偏差有多大,不会自动让回测"变准"。退市股行情补上之前,回测结果应当标注"含幸存者偏差"。
- 异常阈值依赖各板块、各时期的涨跌幅制度,默认值为 **[需核实]**;日报里的异常是"待人工复核的线索",不是已确认的错误。
- 状态表里的 `None` 是诚实的"不知道",不要为了好看用默认值填充。

## 7. 接入提案摘要(待所有者批准,尚未实施)
### 7.1 日报如何每天运行:二选一
| | 方案 A:launchd 单独项(推荐) | 方案 B:`daily.py` 末尾可选调用 |
|---|---|---|
| 隔离 | 日报失败或变慢不影响每日更新,不占 `daily.py` 的单实例锁与 3 小时看门狗 | 在每日任务的锁与看门狗内运行,日报慢会拖累更新;更新失败时反而不跑 |
| 改动 | 不改任何现有代码;要手动装一个 plist(不入库),回滚 = 卸载 | 要改 `daily.py`(受保护入口) |
| 时序 | 不知道更新是否完成,可能读到"部分已更新"的混合态(日报会标注) | 紧接更新之后,无混合态,但只在"今天有更新"时才跑 |
| 时区坑 | 日报默认用北京时间日期;触发时刻要选在两个季节都落在同一个北京日(机器在美国西海岸时约本地 06:00),需所有者核对 | 无 |

先由所有者手动连续运行 5 天,再决定是否装 launchd。

### 7.2 回测如何读取时点状态表(三层,默认关闭、逐层批准)
- **L1 上市满一年**:用 `ipo` 与交易日历算出的 `listed_days` 过滤信号日;`MIN_ROWS` 保留(它还承担"样本够长才算统计量"的作用)。
- **L2 ST**:把 `scan.run` 里"今天名字含 ST 就整只剔除"改成逐日 `is_st` 掩码;历史 ST 来源未定前只能从"自建前向记录"起生效,缺失日期退回现行规则,所以不会更差但也不会更好。
- **L3 停牌与按日期的涨跌停幅度**:需要改 `datasource.limit_pct` 与 `portfolio.run_weights`,与回测审计(T011)的修正提案重叠,等它的结论。
- **防未来函数**:信号层只用 t 日收盘时已知的状态;t+1 日的停牌/涨跌停只能用在成交层。缺信息(`None`)的处理策略(放行/当不可交易)必须显式选择并随结果输出统计。
- 开关关闭时结果必须与现在逐位一致;开关前后的结果差异属于"数据口径变化",不能与策略改进混着解读,退市股补齐前仍标"含幸存者偏差"。
