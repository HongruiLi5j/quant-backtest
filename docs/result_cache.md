# 接口结果缓存（B07 + B08）

重计算的 GET 接口把结果存在进程内存里，输入没变就直接返回；进程重启缓存清空，没有任何东西写盘。

## 哪些接口有缓存

| 接口 | 缓存对象 | 键里有什么 | 容量 / 过期 |
|---|---|---|---|
| `/api/backtest` | `app._backtest_memo` | 市场、策略、品种、参数、成本、起点、行情对象、自选股、临时加载那只股票的文件指纹 | 16 条 |
| `/api/table` | `app._table_memo` | 市场、策略、起点、行情对象、自选股 | 16 条 |
| `/api/trade_list_tracking` | `trade_signals._EVAL_MEMO` | 信号表指纹、各行情文件指纹、北京时间日期和是否已过 15:30 | 8 条 / 600 秒 |
| `/api/stock`（B08） | `app._stock_memo` | 身份（远程/主人/本机）+ 个人模式开关、市场、代码、策略、周期、`detail.input_stamps` | 24 条 / 600 秒 |

`/api/stock` 存的是编码好的 JSON 字节，不是 dict：不可变，调用方改不坏，体积也小。

## 规则

1. **键必须包含所有会影响输出的输入**。数据文件用 `resultcache.file_stamp`（修改时间 ns + 大小 + inode），任何一项变了就是新键；
   `/api/stock` 读哪些文件集中写在 `detail.input_stamps` 的注释里，**以后 `detail.build` 多读一个文件，要同步改这里**。
2. **北京时间 15:30 状态是输入**：行情读取在 15:30 前会丢掉当天的半天 K 线，缓存跨过 15:30 或跨天必须重算。
3. **指纹在计算之前取**。计算过程中文件又被更新，结果会存在旧键下，下一次请求键变了会重算，不会拿旧结果冒充新结果。
4. **不缓存出错结果，也不缓存降级结果**（A 股没取到真实价格，临时网络问题）：`detail.cacheable`。
5. **带个人数据的接口一律不缓存**：持仓（`/api/holdings`）、我的相关（`/api/trade_list_mine`）、会员（`/api/member/*`）、
   后台（`/api/admin/*`）、AI（`/api/ai/*`）、分享、模拟盘、账本摘要等。
   `tests/test_resultcache_b08.py` 的 `TestCacheGuard` 用白名单强制这一点：谁能用缓存是明确列出来的，
   新增缓存用户会让测试失败，逼着改的人先确认它不会把一个人的数据给另一个人看。
6. **每个缓存都必须设 `maxsize`**（LRU 淘汰）；结果依赖时间或键可能漏项时再加 `ttl` 兜底。

## 没有缓存的慢接口

- `/api/trade_list_export`（≈0.39 秒）：生成的 xlsx 里写着「导出时间」（精确到分钟），缓存会让下载文件里的时间是旧的；点一次下载 0.4 秒用户感觉不到，不值得。
