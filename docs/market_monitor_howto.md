# 实时盯盘离线服务（T006 S2）

默认关闭。导入包、构造服务、打开页面或查询状态均不请求上游，也不启动线程。
本阶段没有网站入口；S3 网站接线须另行批准。收盘信号与价格提醒分开展示，盘中价格不重算策略。

可信本机代码创建 `MonitorService()` 后，明确调用 `start()` 开启，`stop()` 一键停止并等待线程/请求进程回收。
重启进程始终停止。每次明确 start 分配新预算，不自动续费或重启；默认 5 次请求，失败也计数。
`Config(request_budget=...)` 仅供本机代码显式配置，范围 1–600；API 不接受预算、路径、轮询频率配置。
每轮至少 60 秒，相邻请求至少 10 秒，同一代码至少 60 秒；默认逐只独立 Provider。
`multi_code_verified=False`；只有真实验证并明确修改本机配置为 True 后才合并多代码请求。
连续三次请求失败或质量异常暂停；存储失败立即暂停提醒并显示 storage_error，需要先排查后重建服务。
单次请求在独立 spawn 进程内运行；父线程在 timeout + 2 秒（启动余量）截止后 terminate/join，必要时 kill/join。
正常 stop 以 50ms 间隔观察取消，不依赖 DNS 自行返回。

API 使用 `handle(service, action, body, is_local_owner=True)`。所有者布尔上下文缺省为 False；必须由未来 S3 的可信认证产生，不能相信浏览器自报。
支持 status/start/stop/watch_add/watch_remove/rule_set/rule_delete/alerts/trend/export_quality。
watch_add 必须来自所有者明确操作，无自动订阅；最多五只沪深 A 股六位代码。
规则方向 up/down，threshold 有限正数，cooldown_seconds 默认 300，daily_limit 默认 3。
首次有效采样只建基线；质量异常/断线/配置变更/重启重建基线；冷却及每日次数持久化，重启不清零。
JSON 请求体最多 8KB，拒绝未知键、重复键和非法数值；错误仅返回固定代码。

盘中快照固定写入 `data/market_monitor/snapshot_*.json`，目录 700，文件 600，逐层拒绝符号链接，独占创建。
快照含关注列表、规则、提醒历史、每只最多 90 个最近有效采样点、质量分类计数及提醒次数。
每次写完整快照并 fsync；旧快照保留，尚无自动清理，长期使用需评估磁盘容量。
存储损坏不静默恢复空配置或跳过丢失的提醒。质量导出只有计数/原因，不包含上游原文、名称、请求头或凭据。

源时间为上游第 31 字段解释的北京时间，具体供应商时间语义未获官方证实；接收时间为本机收到响应的时间；触发时间为本机评估提醒的时间。
统一带 +08:00 的北京时间显示。源行情年龄不等同于网络延迟。
trend 仅显示最近 30 分钟的“采样价格”，不是完整分钟 K 线。近 5/15 分钟变化取最新采样与目标时刻之前最近采样比较，返回实际跨度秒数；缺少覆盖时显示“数据不足”。
交易钟表时段为周一至周五 9:30–11:30、13:00–15:00。未提供交易日历时不确认节假日，依源时间是否过旧拒绝提醒，仍受预算限制。

只读收盘信号来自 `data/daily/trade_list_cn.json`：version=4、market=cn、data_date、generated_at、strategies 各策略 rows 的 code/action/last_date。
只提取明确关注代码，保留策略及信号日期；不取 exceptions，不重新计算或改动清单，也不改主策略设置。
文件缺失、格式不符、未来日期或不能确认收盘后发布时显示“无信号”。所有策略分别保留，避免同代码多策略结论被合并误解。

已知局限：Mac 睡眠中断采集；采样会漏掉间隔内穿越；无可靠停牌标志；成交量单位未核实；腾讯地址无官方许可，仅限所有者已知情的个人自用验证；多代码尚未真实验证；真实 DNS、连续运行和广发对照未验收。
提醒只是所有者设置的价格条件，不代表策略买卖建议或保证送达。

回滚：调用 stop()，取消调用 start() 并保持默认关闭即可；本阶段没有修改网站、策略或任何现有数据。保留快照供核对，不进行迁移或删除。

# S3：实时盯盘接入网站（T006 S3，仅个人模式）

## 怎么开启
1. 个人模式开启（根目录 `personal_mode.json` 的 `enabled` 为 `true`）。关闭时 `/api/market_monitor/*` 全部 404，不创建调度器、不启动任何线程。
2. 打开网页，导航里多了“盯盘”。**默认不采集**：必须点“开始盯盘”（或本机 POST `/api/market_monitor/start`）才启动后台线程。
3. 重启网站进程后一律是停止状态，不会自动恢复；需要再点一次。点“停止盯盘”会等待线程与请求子进程回收。

## 监控哪些股票
`我的持仓`（T013 台账里仍持有的代码；台账缺失或为空时降级为空并只写一条日志）→ `cn 自选` → `今日买卖最新清单前 N 只`（默认 20，页面可改 0–60），按此优先级合并去重，**总数硬上限 60 只**，超过就从信号股开始截断，页面提示“已截断”。只读这三个来源，不改任何来源文件；每轮开始时重新读取。

## 页面上看什么
- 运行状态、已请求次数/预算、监控只数、已完成轮数、暂停原因。
- 监控股票表：代码、名称、现价、涨跌（相对昨收）、采集时间（北京时间）、告警状态（无目标价/已布防/已触发）、来源、数据质量。
- 告警历史；配置（采样间隔 30–3600 秒，默认 60；信号前 N 只）。页面每 10 秒只向本机接口取一次快照，离开页面即停止并清空页面里的报价。

## 速率与预算（继承 S1/S2，接口不能改）
同一代码至少 60 秒、相邻请求至少 10 秒、单请求最多 5 只（多代码写法尚未真实验证，默认逐只）；每次 start 的请求预算上限 600，用完暂停并显示 `budget_exhausted`，需手动再点开始。连续三次失败/质量异常也会暂停。采样间隔设为 30 秒也不会突破“每只 60 秒”。`/config` 只接受 `interval` 与 `top_n`，其他键一律 400。
**注意：逐只请求时 60 只股票一轮约需 10 分钟（每 10 秒一只），所以名单越大，每只的实际刷新越慢。**

## 到价提醒
对每只来自今日买卖清单、且清单行带有目标买入价/目标卖出价的股票：价格下穿目标买入价、上穿目标卖出价时提醒（复用 S1 的 `alert_step`：首次只建基线、严格递增时间、冷却 300 秒、每日最多 3 次，冷却与次数落盘，重启不清零）。Mac 通知走 `src.notify`，不可用时只记日志。**目前已发布的清单行里没有目标价字段（`buy_price`/`sell_price`），因此此刻不会产生到价提醒**，页面显示“无目标价”；等清单带上这些字段后自动生效。

## 隐私与安全
- 所有接口要求：可信本机（Host 合法、无代理/隧道头、非分享链接）+ 已登录 + `X-Requested-With: dashboard`；写接口还要 Origin 校验。任何一项不满足统一返回同一个 403，不区分原因。
- 报价只在内存里，不进离线整站导出、分享页面、浏览器存储或日志；落盘的只有告警、冷却计数和质量计数（`data/market_monitor_watch/`，目录 700/文件 600，与 S2 的 5 只快照目录分开）。日志只写轮次计数，不写价格或代码。
- 前端全部用 `textContent`，不用 `innerHTML`；上游返回的股票名称只当文本显示。

## 注意事项
- 腾讯公开接口没有使用许可，也没有官方文档：**仅限个人、少量股票自用**，延迟与准确性未验证，可能随时失效或限流。
- 只在 A 股连续竞价时段采集（北京时间 9:30–11:30、13:00–15:00，周一至周五；对应洛杉矶夏令时前一晚 18:30–20:30、22:00–24:00）。收盘后线程自动不再请求（停留在“等待开盘时段”，需要你点停止才会退出）。节假日没有日历，靠行情时间是否过旧拦截。
- Mac 睡眠会中断采集；采样会漏掉两次采样之间的穿越。
- 盘中价格不是收盘价，不用来重算策略信号；提醒只是价格条件触发，**不构成投资建议**。

## 回滚
点“停止盯盘”；或把 `personal_mode.json` 的 `enabled` 改为 `false`（路由立即 404；已启动的线程需先停止）。保留 `data/market_monitor_watch/` 供核对，不删除。

# S3b：实时分析（T006 S3b，仅个人模式，随盯盘一起开启）

盯盘页顶部多了“实时分析”三栏，只有点了“开始盯盘”才有数据（不额外请求行情，用的是盯盘已采到的报价；速率与预算和 S3 完全相同）。所有结果**仅参考，未经分钟级回测验证**，盘中价格不是收盘价。

## 三块
- **执行提醒（A）**：开盘后 5 分钟内、还没持有的买入信号 → “买入窗口打开”（绿）；涨停且清单里有买入信号 → “涨停不可买，追不进”（红）；跌停且清单有卖出信号或你持有该股 → “跌停不可卖”（红）；持仓股当日跌幅 > 5% → “持仓异常波动，考虑止损”（红）。涨跌停幅度：主板 10%、创业板/科创板 20%、ST 5%；价格恰好等于涨/跌停价算涨/跌停。
- **信号追踪（B）**：今日买卖清单每条信号的开盘价（取行情的开盘价字段，缺失退回当日第一笔报价）、现价、相对开盘涨跌%、距涨跌停%。买入/加仓信号另有“累计收益%”= 现价/开盘价-1（同时记录 `return_since_signal` = 现价/信号日收盘价-1；清单目前没有“建议开盘价”字段，用信号日收盘价代替）。顶部汇总行：条数、赢/亏（赢 = 现价高于开盘价）、平均、中位数。样本通常只有几条，只能观察，不能当作“策略正确率”。
- **新机会（C）**：在名单（≤60 只）上用日线因子的盘中版本：开盘后 5 分钟起的动量（现价/开盘价-1，>3%）、放量（当日累计成交量 / 20 日均量 >2 倍，均量读本地日线缓存）、短期突破（现价相对“此前”当日最高/最低价超过 1%；若用含当前价的最高价则恒为 0，所以不含当前价）。阈值严格大于，可在代码里配置。持仓股触发负向版本 → 红色“考虑卖出”；未持仓股触发正向版本 → 橙色“关注”。每条带“自触发 x%”（`return_since_trigger`）。

## 数据与文件
- 追踪数据追加写入 `data/market_monitor_intraday/<日期>.jsonl`（目录 700、文件 600、拒绝符号链接；约每分钟一批；`type` 为 `track` 或 `trigger`），未来 T012/S3c 可读。不改信号账本。重启后页面上的事件清空（内存），jsonl 保留。
- 页面数据随 `/api/market_monitor/quotes` 的 `intraday` 字段返回（`app.py` 不在本阶段允许范围，没有登记独立路由；`wiring.handle_intraday_events` / `handle_intraday_tracking` 已写好，登记路由是 app.py 里两行）。不进离线导出、分享页。
- 注意：逐只请求时 60 只一轮约 10 分钟，所以“开盘 5 分钟窗口”很可能在该股第一次报价到来前就过了；名单越小越准。成交量单位按“手”(×100) 估计，未核实，放量项可能偏差。
